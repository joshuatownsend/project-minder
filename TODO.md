- [ ] **Gate the next `DERIVED_VERSION` bump on shipping the worker-ingest fix** — The packaged-server worker default (#431, PR #435) is on `main` but **not in any release**: 1.10.1 and earlier run the reconcile on the main thread, where it monopolizes the event loop and takes the whole dashboard down for the duration (measured at ~3 hours on a 6,078-session corpus). So a release that bumps `DERIVED_VERSION` *without* also carrying #435 hands every existing install another multi-hour blackout. Either ship the worker fix first, or ship both in the same version — never the bump alone. Deliberately not released on its own (2026-08-12): batched for a later version at the user's call.

## Demo mode coverage

*Driver: a route-by-route audit on 2026-08-12 (while recapturing the landing page) measured what `MINDER_DEMO=1` actually covers. The answer is about half of what the marketing screenshots need, and the gaps are not where the flag's description implies. Demo mode is the mode meant for first-run, screenshots and demos, so a screen that renders empty or leaks real data there fails in exactly the situation it exists for. Findings recorded here rather than as issues because they are one coherent gap, not N defects; `/usage` (#443) and `/workflows` (#441) are already filed individually.*

Cause: `src/app/layout.tsx:43-48` calls `readConfig()` → `getDevRoots(config)` inline in a server component, so it never passes through the `data/index.ts` façade or any route where a `demoMode()` guard could apply. `/hooks` is the same shape — no guard on its route — and prints the real home path (`C:\Users\joshu`).

## Memory Observatory

*Inspired by [Nicolas Bustamante's "Agent Memory Engineering"](https://x.com/nicbstme/status/2050301124314563025), comparing how Claude Code, Codex CLI, and Hermes implement agent memory. Key findings: clever architectures (vector DBs, knowledge graphs, dedicated memory agents) all lost to **LLM + typed markdown + bash**; the interesting axis is the read/write **discipline** the agent follows, not the data structure; memory is a **hint surface, not authority** — every body read should be wrapped in an age-aware "verify before recommending" reminder. Phase 1 (Freshness + Telemetry + Budget + MEMORY.md index awareness on `/memory`) is in active planning per the approved plan at `~/.claude/plans/i-recently-read-this-temporal-crane.md`; the entries below are the deferred follow-on phases, in priority order.*

- [ ] **Wave M.2 — Cross-harness memory bridge (Codex + Gemini)** — **Status (2026-05-12):** deferred after Phase 1 + M.1 + M.3 + M.4 shipped (PRs #118 / #119 / #121). M.2 is the only remaining Memory Observatory wave. **Plan doc**: see `C:\Users\joshu\.claude\plans\i-recently-read-this-temporal-crane.md` for the upstream framing (Nicolas Bustamante's "Agent Memory Engineering" article comparing Claude Code / Codex CLI / Hermes memory layers), the article principles → Project Minder opportunities table, and the Phase 1 → M.1 → M.4 → M.2 dependency rationale. The plan doc and this TODO entry are intentionally redundant on the M.2 spec itself; the plan doc adds the *why* (article framing, cross-wave dependency story) that's not duplicated here. Addresses the article's central frustration: memory rules taught to Claude Code don't transfer to Codex / Gemini despite sharing the same filesystem, because each model is post-trained on its harness's specific memory layer (Claude Code's typed taxonomy + always-loaded MEMORY.md index + age-aware `<system-reminder>` framing on every body read vs Codex's offline extract+consolidate pipeline + lazy `memory_summary.md` load + on-demand handbook reads). Extend the existing adapter registry from session-read to full memory IO, then ship a diff/sync UI so canonical rules can be authored once and pushed across stores. **Upstream research needed before PLAN**: (a) **Codex memory layout** — per the article, Codex's memory folder has its own `.git/`, a `memory_summary.md` (5K-token cap, injected per turn), a full `MEMORY.md` handbook, and a `skills/` tree; discover exact path under `$CODEX_HOME/`; document the `MemoriesUsageKind` enum values (`MemoryMd`, `MemorySummary`, `RawMemories`, `RolloutSummaries`, `Skills`) so the bridge can expose per-kind usage.
